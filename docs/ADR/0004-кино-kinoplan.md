# ADR-0004. Кино — данные с сайтов кинотеатров через API Kinoplan, без хранения сеансов в базе

**Дата:** 2026-09-17
**Статус:** принято

## Контекст

`docs/plan.md` (раздел 9) отмечал «Кино» как 🔴 блокер: в РФ нет публичного
API с сеансами и ценами. Предлагались три варианта — (а) договор с билетным
агрегатором, (б) партнёрский кабинет для кинотеатров, (в) парсинг сайтов
кинотеатров («не рекомендую»).

Пользователь выбрал свой вариант, близкий к (в), но с явным ограничением:
приложение само забирает расписание сеансов, а покупка (выбор места)
происходит на стороне кинотеатра — по нажатию на сеанс человек уходит на
сайт кинотеатра. Отдельно было решено ограничиться источниками строго
уровня «сайт самого кинотеатра», не трогая сторонние агрегаторы
(Яндекс.Афиша, kinoafisha.info, afisha.ru) — они юридически рискованнее:
Яндекс, в частности, известен тем, что активно преследует скрейперов.

## Находка: все кинотеатры (кроме Дербента) работают на одной платформе

Технический разбор сайтов реальных кинотеатров трёх запущенных городов
показал, что 4 из 5 кинотеатров — это SPA-обёртки на платформе **Kinoplan**
(kinoplan.ru, поставщик билетных систем для региональных кинотеатров),
обращающиеся к собственному JSON REST API
(`https://kinokassa.kinoplan24.ru`) с публичным токеном, встроенным прямо
в HTML-код каждого сайта.

Формат найден анализом JS-бандла сайта kino-paramax.ru (маршруты API — как
строковые константы внутри собранного `app.min.*.js`), затем проверен
живыми запросами для всех четырёх кинотеатров:

| Кинотеатр | Город | Сайт | Kinoplan cinema_id | Kinoplan city_id |
|---|---|---|---|---|
| Парамакс | Махачкала | kino-paramax.ru | 488 | 173 |
| Синема Холл | Махачкала | cinemahall24.ru | 2366 | 173 |
| Октябрь | Махачкала | october-kino.ru | 567 | 173 |
| Москва | Каспийск | крцмосква.рф | 731 | 280 |

Обязательные заголовки: `X-Application-Token` (токен сайта),
`X-Platform: widget`, `X-Preferred-Language: ru`. Ключевые эндпоинты:
`GET /api/v2/app` (бутстрап: título кинотеатра, `city_id`) и
`GET /api/v2/release/playbill?city_id=&date=` (фильмы и сеансы на дату).

**Дербент** (кинотеатр «Hayal Cinema») собственного сайта не имеет — только
телефон и Telegram. Под условие «только сайты кинотеатров» источника для
него сейчас нет; `CinemaService.getSchedule` в этом случае просто вернёт
пустой список (в базе для Дербента нет ни одной записи `Cinema`) — это
корректное отражение реальности, а не ошибка.

## Юридическая оговорка

Это API того же сайта, которым пользуется сам кинотеатр — не сторонний
агрегатор, поэтому риск ниже, чем при скрейпинге Яндекс.Афиши или
kinoafisha.info. Но это всё ещё **не документированный публично** API:
токен предназначен для встраивания в сайт кинотеатра, а не для
распространения третьим лицам, и ToS сайтов кинотеатров формально может
запрещать автоматический доступ. Это не безрисковая зона — при появлении
претензий от кинотеатра или Kinoplan решение нужно будет пересмотреть.

## Ссылка на конкретный сеанс

Сначала казалось, что её нет: на сайте кинотеатра покупка открывается
JS-виджетом, и адрес страницы при этом не меняется. Но разбор самого виджета
(`kinowidget.kinoplan.ru/js/kinowidget.min.js`, метод `render`) показал, что
адрес у него всё же есть — виджет собирает его из трёх идентификаторов и на
телефоне открывает обычной страницей через `window.open`:

```
https://kinowidget.kinoplan.ru/<kinoplan_cinema_id>/<release_id>/<seance_id>
```

Открывается сразу выбор мест нужного сеанса — с залом, датой и ценами.
Проверено для «Парамакса» (488) и «Москвы» (731). Все три идентификатора у
нас есть: кинотеатр — в `Cinema.kinoplanCinemaId`, фильм и сеанс приходят в
ответе `/api/v2/release/playbill`. Ссылка собирается в `buildTicketUrl`
(`apps/api/src/modules/cinema/kinoplan-client.ts`).

Маршрута `/seances`, на который ссылка вела раньше, на сайтах нет вовсе —
открывалась пустая страница «сеансов нет». Сами сайты для фильма используют
`/release/<release_id>?date=<дата>`; это годится как запасной вариант, если
виджет когда-нибудь перестанет открываться напрямую.

## Решение: сеансы и фильмы не хранятся в Postgres

В `docs/plan.md` эскиз схемы (`cinemas · movies · halls · showtimes`)
предполагал сценарий (б) — кинотеатры сами вносят сеансы через партнёрский
кабинет, то есть мы были бы источником истины. При интеграции с готовым
Kinoplan это не так: сеансы — целиком чужие, ежедневно меняющиеся данные.

Вместо персистентности — тот же паттерн, что уже применён для погоды
(`WeatherService`): `CinemaService.getSchedule()` обращается к Kinoplan по
требованию и кеширует ответ в Redis (`cinema:schedule:<cityId>:<date>`,
TTL 30 минут). В Postgres — только модель `Cinema` (адрес, город, данные
для обращения к Kinoplan, статус) — редкий справочник, которым управляет
админ, ровно как `City`.

Отклонённая альтернатива — периодическая синхронизация в БД через фоновую
задачу (`bullmq`, уже установлен в `apps/api/package.json`, но нигде не
подключён). Отклонена как избыточная инфраструктура для задачи уровня
«запрос по требованию + кеш на 30 минут»: сама Kinoplan уже хранит данные
достоверно и с актуальным состоянием мест, синхронизация добавила бы только
риск рассинхронизации и лишний код без выигрыша. К `bullmq` стоит вернуться,
когда появится задача, для которой кеш недостаточен (например, push-
уведомление о премьере — тогда нужен именно фоновый обход, а не ответ на
запрос пользователя).

Обработка частичного отказа: `Promise.allSettled` по всем кинотеатрам
города — падение одного (протухший токен, сетевой сбой) не должно скрывать
расписание остальных, и не считается ошибкой уровня API (в отличие от
погоды, где источник один, и его недоступность — это `502
WEATHER_UNAVAILABLE`). Пустой список сеансов — валидный ответ `200`.

## Как добавить новый Kinoplan-кинотеатр

1. Открыть сайт кинотеатра, посмотреть исходный HTML — если в `<head>` есть
   `window.kinositeSettings={token:"..."}`, это Kinoplan.
2. Вызвать `GET https://kinokassa.kinoplan24.ru/api/v2/app?with_cities=true`
   с найденным токеном и заголовками из раздела выше — в ответе будет
   `cinemas[0].id` (kinoplanCinemaId) и `cinemas[0].city_id`
   (kinoplanCityId).
3. Создать запись `Cinema` (через `POST /api/v1/cinema` в панели управления
   или добавить в `apps/api/prisma/seed.ts`) с этими значениями и `cityId`
   нашего города (по `slug`).
