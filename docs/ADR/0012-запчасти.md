# ADR-0012: Запчасти и комплектующие

**Статус:** принято (2026-10-05)

## Контекст

Запчасти — не отдельный мир, а часть техники: «рулевая рейка» бывает у
легковой машины, грузовика и спецтехники, «дисплей» — у телефона, ноутбука и
телевизора. Покупатель ищет не «запчасть вообще», а деталь для своей техники
и своей модели; продавец указывает номера и то, к чему деталь подходит.
Нельзя ни заводить второй каталог объявлений, ни копировать справочники марок
и моделей.

## Решение

### Модель

```
тип техники → «Запчасти и комплектующие» → группа деталей → деталь → совместимость
```

- **Тип техники** — 12 штук (`PartsEquipmentType`): легковые, грузовики,
  мото, спецтехника, водный транспорт, телефоны, ноутбуки, компьютеры,
  телевизоры, бытовая техника, климатическая техника, прочее оборудование.
  Новый тип (планшеты, камеры) — одна запись в
  `packages/shared/src/constants/parts/equipment-types.ts` и таксономия.
- **Подкатегория на тип техники** (12 листьев дерева объявлений). Дерево
  категорий строго двухуровневое, поэтому «тип техники → запчасти» — это лист
  раздела, а не третий уровень. Общего «Все запчасти» нет.
- **Группа и деталь** — обычные атрибуты `partGroup` и `partItem` (деталь
  зависит от группы, как модель от марки), справочники `part_group_<тип>` и
  `part_item_<тип>` сеются из таксономии (156 групп, 617 деталей, ≈1 060
  написаний-синонимов).
- **Производитель, тип и состояние детали** — три разных поля (с 2026-10-07):
  - производитель (`partManufacturer`) — код справочника `part_manufacturer`
    (один на всю технику, ≈100 записей: Toyota, Denso, Bosch, KYB, CTR, Masuma…).
    У записи в `meta.equipment` — типы техники, где она уместна: форма и
    фильтр автозапчастей не показывают Indesit, бытовая техника — KYB.
    `meta.machineBrand` — название совпадает с маркой техники (Toyota,
    Samsung): во фразе поиска такое слово читается как техника;
  - тип (`partOriginality`, «Тип детали») — только «Оригинал» и «Аналог»;
    из производителя НЕ выводится;
  - состояние (`partCondition`) — «Новая», «Б/У», «Восстановленная».
    «Контрактная» — это «Оригинал» + «Б/У» (миграция переводит старое
    значение так, если тип не указан); «На запчасти» и «Под восстановление»
    стали «Б/У». У «Восстановленной» — подсказка «укажите в описании, что
    было восстановлено», а не обязательное поле.
    В карточке пара «состояние + тип» — одной подписью: «Б/У оригинал»,
    «Новый аналог» (`partStateLabel`). Единицы цены — существующие (`total`,
    `per_unit`), «за комплект/пару» — `partSaleUnit`.
- **Слой запчасти** (две таблицы, миграция `20261006100000_listing_parts`):
  `listing_compatibility` (марка, модель, кузов, годы от/до, двигатель,
  модификация — по строке на «к чему подходит») и `listing_part_numbers`
  (OEM, каталожный, номер производителя, артикул; ключ `number_key` —
  без регистра и знаков, кириллические двойники заменены латиницей).
  Марка и модель — коды из справочников самой техники (`car_brand`,
  `phone_model`…); где справочника нет, текст. Это не атрибуты, потому что
  атрибут хранит одно значение, а совместимость — список.
- **Несколько совместимостей одной детали**: одна рейка подходит к Succeed
  NCP165 2015–2020 1NZ-FE, Probox NCP160 2014–2020 и Probox NCP165 — это три
  строки одного объявления, а не три детали. Строки не перемножаются: «Succeed
  NCP160» эту деталь не найдёт. Модификация — фильтр там, где у моделей бывают
  версии (легковые, грузовики, спецтехника, телефоны, ноутбуки, бытовая и
  климатическая техника); кузов — только у легковых.
- **Кроссы номеров** — таблица `part_number_crosses` (миграция
  `20261007100000_part_condition_type_crosses`): «производитель + номер →
  производитель + номер», источник и дата подтверждения. Пустая: кроссы не
  выводятся автоматически (одинаковая деталь двух аналоговых производителей —
  ещё не кросс), только из подтверждённого каталога.
- **Старые объявления** не ломаются: объявление без слоя — обычное, `part`
  у него `null`. Миграция переносит значения старых атрибутов
  «Марка/Модель/Тип запчасти» в слой и новые атрибуты.

### Поиск

- Фильтры совместимости (марка + модель + год + кузов + двигатель) — ОДИН
  `EXISTS` по одной строке слоя: «Succeed 2023» не найдёт деталь с
  «Succeed 2014–2020» и «Probox с 2014».
- Номер ищется по ключу, в том числе по началу, и находит деталь без
  названия: «90915-YZZD1», «90915yzzd1», «90915 yzzd1».
- Умный поиск — **локальный разбор без модели** (`SMART_SEARCH_PARSER=local`):
  индекс названий деталей (`packages/shared/src/search/parts.ts`), сканер
  номеров/кузовов/двигателей, `decideParts` выбирает тип техники по
  словам («на стиралку»), марке/модели каталога («на суксид» — легковая) и
  открытой категории; когда не уверен — **уточнение с вариантами**
  («экран» → телефон / ноутбук / телевизор), без вызова модели.
  Приоритет: номер → точное название → известная марка/модель → тип
  техники → синоним → безопасная опечатка → контекст. Нераспознанное
  уходит в `smart_search_unrecognized` (без персональных данных).
- Производитель, тип и состояние во фразе: «рейка суксид KYB», «б/у оригинал
  рейка ncp165», «новая denso» (основной тип техники производителя),
  «Denso 123456» (производитель + номер; номер ищется и сам по себе),
  «контрактная» = Б/У + Оригинал. «Восстановленная» без «оригинал/аналог» —
  вопрос «Уточните тип детали». Марка техники («рейка Toyota») — совместимость,
  а не производитель; незнакомое слово производителем не становится.
  Кузов («NCP165») и мотор («1NZ») без других слов — подсказка «легковые».
- Заголовок формы подачи («Рулевая рейка Toyota Succeed NCP165 2015»)
  подсказывает подкатегорию запчастей, группу и деталь и предлагает первую
  строку «Подходит к» — «Добавить» / «Изменить»; без нажатия не записывается.

### Приложение

Те же экраны объявлений: форма подачи и правки получают редактор «Номера
детали» и «Подходит к» (`PartLayerEditor`: несколько строк, удаление, поле
модификации по типу техники), экран объявления — блок «Запчасть»
(деталь, производитель, тип, состояние, номера) и «Подходит к» (до пяти строк,
остальные по «Показать все») — `PartBlock`. Фильтры строятся из атрибутов
категории; поля совместимости — отдельным блоком «Подходит к». Отдельного
экрана поиска запчастей нет.

## Ограничения и осознанные отклонения

- Дерево двухуровневое: «тип техники → запчасти» реализовано листьями, а не
  третьим уровнем.
- Справочник автомобилей без поколений и кузовов: кузов, двигатель,
  модификация — свободный текст; модель вне справочника хранится текстом.
- Автоматической совместимости и базы кросс-номеров нет: таблица кроссов
  пустая, совместимость не выдумывается (одинаковый мотор 1NZ-FE не делает
  деталь подходящей ко всем машинам с ним).
- Производитель, совпадающий с маркой техники (Toyota, Samsung, LG), во фразе
  поиска читается как техника; выбрать «производитель Toyota» можно фильтром.
- Производитель вне справочника кода (добавленный из панели) виден в форме и
  фильтре, но умный поиск узнаёт его по названию только после добавления в
  `PART_MANUFACTURERS`.
- «Новая Denso» без детали и техники — раздел основного типа техники
  производителя (у Denso — легковые).
- Честные неоднозначности остаются вопросом: «экран», «насос», «плата»,
  «камера», «аккумулятор», «дисплей», «двигатель», «блок питания»,
  «аккумулятор самсунг», «матрица lg».
- Заголовок «Toyota Camry с новым двигателем» старый классификатор по-прежнему
  относит к автозапчастям (подсказка, пользователь меняет одним нажатием).
