# ADR-0012: Запчасти и комплектующие

**Статус:** принято (2026-10-05)

## Контекст

Запчасти — не отдельный мир, а часть техники: «рулевая рейка» бывает у
легковой машины, грузовика и спецтехники, «дисплей» — у телефона, ноутбука и
телевизора. Покупатель ищет не «запчасть вообще», а деталь для своей техники
и своей модели; продавец указывает номера и то, к чему деталь подходит.
Нельзя ни заводить второй каталог объявлений, ни копировать справочники марок
и моделей.

## Решение

### Модель

```
тип техники → «Запчасти и комплектующие» → группа деталей → деталь → совместимость
```

- **Тип техники** — 12 штук (`PartsEquipmentType`): легковые, грузовики,
  мото, спецтехника, водный транспорт, телефоны, ноутбуки, компьютеры,
  телевизоры, бытовая техника, климатическая техника, прочее оборудование.
  Новый тип (планшеты, камеры) — одна запись в
  `packages/shared/src/constants/parts/equipment-types.ts` и таксономия.
- **Подкатегория на тип техники** (12 листьев дерева объявлений). Дерево
  категорий строго двухуровневое, поэтому «тип техники → запчасти» — это лист
  раздела, а не третий уровень. Общего «Все запчасти» нет.
- **Группа и деталь** — обычные атрибуты `partGroup` и `partItem` (деталь
  зависит от группы, как модель от марки), справочники `part_group_<тип>` и
  `part_item_<тип>` сеются из таксономии (156 групп, 617 деталей, ≈1 060
  написаний-синонимов).
- **Производитель детали, оригинальность, состояние, вид продажи, наличие** —
  три разных понятия не смешаны: производитель (`partManufacturer`: Denso,
  Bosch…) ≠ оригинальность (`partOriginality`: оригинал/аналог) ≠ состояние
  (`partCondition`: новая, б/у, контрактная, восстановленная…).
  Единицы цены — существующие (`total`, `per_unit`), «за комплект/пару» —
  `partSaleUnit`.
- **Слой запчасти** (две таблицы, миграция `20261006100000_listing_parts`):
  `listing_compatibility` (марка, модель, кузов, годы от/до, двигатель,
  модификация — по строке на «к чему подходит») и `listing_part_numbers`
  (OEM, каталожный, номер производителя, артикул; ключ `number_key` —
  без регистра и знаков, кириллические двойники заменены латиницей).
  Марка и модель — коды из справочников самой техники (`car_brand`,
  `phone_model`…); где справочника нет, текст. Это не атрибуты, потому что
  атрибут хранит одно значение, а совместимость — список.
- **Старые объявления** не ломаются: объявление без слоя — обычное, `part`
  у него `null`. Миграция переносит значения старых атрибутов
  «Марка/Модель/Тип запчасти» в слой и новые атрибуты.

### Поиск

- Фильтры совместимости (марка + модель + год + кузов + двигатель) — ОДИН
  `EXISTS` по одной строке слоя: «Succeed 2023» не найдёт деталь с
  «Succeed 2014–2020» и «Probox с 2014».
- Номер ищется по ключу, в том числе по началу, и находит деталь без
  названия: «90915-YZZD1», «90915yzzd1», «90915 yzzd1».
- Умный поиск — **локальный разбор без модели** (`SMART_SEARCH_PARSER=local`):
  индекс названий деталей (`packages/shared/src/search/parts.ts`), сканер
  номеров/кузовов/двигателей, `decideParts` выбирает тип техники по
  словам («на стиралку»), марке/модели каталога («на суксид» — легковая) и
  открытой категории; когда не уверен — **уточнение с вариантами**
  («экран» → телефон / ноутбук / телевизор), без вызова модели.
  Приоритет: номер → точное название → известная марка/модель → тип
  техники → синоним → безопасная опечатка → контекст. Нераспознанное
  уходит в `smart_search_unrecognized` (без персональных данных).
- Заголовок формы подачи («Рулевая рейка Toyota Succeed») подсказывает
  подкатегорию запчастей, группу и деталь.

### Приложение

Те же экраны объявлений: форма подачи и правки получают редактор «Номера
детали» и «Подходит к» (`PartLayerEditor`), экран объявления — блок
`PartBlock`, фильтры строятся из атрибутов категории. Отдельного экрана
поиска запчастей нет.

## Ограничения и осознанные отклонения

- Дерево двухуровневое: «тип техники → запчасти» реализовано листьями, а не
  третьим уровнем.
- Справочник автомобилей без поколений и кузовов: кузов, двигатель,
  модификация — свободный текст; модель вне справочника хранится текстом.
- Автоматической совместимости и базы кросс-номеров нет: аналоги и кроссы
  заложены только архитектурно (виды номеров), совместимость не выдумывается.
- Честные неоднозначности остаются вопросом: «экран», «насос», «плата»,
  «камера», «аккумулятор», «дисплей», «двигатель», «блок питания»,
  «аккумулятор самсунг», «матрица lg».
- Заголовок «Toyota Camry с новым двигателем» старый классификатор по-прежнему
  относит к автозапчастям (подсказка, пользователь меняет одним нажатием).
