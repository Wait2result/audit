# ADR-0010. Геолокация объявлений: точка и радиус, адреса, телефон

**Статус:** принято (2026-09-29)

## Контекст

До этого решения место объявления описывалось городом из справочника,
районом города (выбирался вручную из списка) и свободной строкой адреса.
Поиск «рядом» работал только от GPS человека и только по трём городам, у
которых есть районы. Из этого вытекало:

- сёла без статуса города (Манаскент, Манас, Каякент…) нельзя было ни
  указать, ни найти — ближайшим «городом» объявления становился Каспийск;
- «Манаскент + 25 км» было невыразимо: круг строился только вокруг
  человека, и без разрешения на геолокацию его не было вовсе;
- район выбирался руками и часто не тот; адрес не был связан с точкой;
- телефон принимался в любом виде, «8950» сохранялся как номер.

## Решение

### Модель места

Каждое объявление хранит точку (`latitude`/`longitude` + `geom geography`
с индексом GIST) и разобранный адрес: `country`, `region`, `district`
(административный район), `city_district` (район города), `city`,
`settlement`, `street`, `house_number`, `formatted_address`,
`location_accuracy` (`house | street | settlement | point`) и
`address_visibility` (`exact | approximate`).

- **Район не выбирается человеком** — он приходит от геокодера вместе с
  адресом. Село живёт без города: `city = null`, `settlement = 'Манаскент'`.
- **Точка обязательна и проверяется строго** (конечные числа, диапазоны,
  CHECK в базе: широта и долгота заданы вместе). За пределами Дагестана —
  только предупреждение в форме: геокодер иногда ставит приграничное село
  за границу.
- **Точка не выдумывается.** Её ставит человек (подсказка, карта, кнопка
  «Моё местоположение»); GPS молча не подставляется. Если адрес по точке
  не нашёлся или геокодер недоступен, объявление сохраняется с точкой.
- `city_id` остаётся (ось всего приложения): сервер ставит ближайший
  город из справочника.

### Что видят другие

По умолчанию частный продавец показывает населённый пункт и улицу без дома,
а на карте — круг «примерно здесь» вокруг точки, округлённой до ~1 км.
Разделы `services` и `business` по умолчанию показывают точный адрес. Точные
координаты хранятся всегда и работают в поиске — от видимости зависит
только выдача наружу (`publicLocation` в `listing-location.ts`).

### Поиск: точка + радиус

Параметры ленты: `latitude`, `longitude`, `radiusKm ∈ {1,5,10,25,50,100}`
(сервер принимает до 300) или `regionWide=true` («Весь Дагестан»). Всё
считается в PostgreSQL/PostGIS, клиент расстояний не вычисляет:

```sql
ST_DWithin(l.geom, :point, :meters)
OR (l.geom IS NULL AND l.city_id IN (
  SELECT id FROM cities WHERE ST_DWithin(city_point, :point, :meters)))
```

Вторая ветка — для старых объявлений без своей точки: они попадают в круг
по центру своего города, но расстояние в карточке у них не показывается.
«Сначала ближе» сортирует в базе с курсором `(расстояние, id)` — страницы
без повторов и пропусков. Остальные фильтры, поиск по тексту, сортировки и
счётчик работают поверх круга без изменений.

Место поиска выбирает человек на экране «Где искать»: поиск села или
адреса, «Моё местоположение» (разрешение спрашивается только здесь), недавние
места, карта с кругом радиуса. Выбор хранится на устройстве; пока ничего не
выбрано — центр города приложения и 25 км.

### Геокодирование

Прослойка `GeocodingService` (`apps/api/src/modules/geo`) с поставщиками за
интерфейсом `GeocodingProvider`:

| Задача | Поставщик по умолчанию | Почему |
|---|---|---|
| Подсказки при наборе (`GET /geo/suggest`) | Photon | создан для автодополнения, ищет по префиксу, приоритет — рядом с точкой и внутри Дагестана |
| Адрес по точке (`GET /geo/reverse`) | Nominatim | точнее разбирает адрес, отдаёт район города и административный район |

Оба — данные OpenStreetMap без ключа. Кэш в Redis (сутки для найденного,
час для пустого ответа), склейка одинаковых запросов в полёте, таймаут 6 с,
очередь Nominatim не чаще раза в секунду (его правило), ограничение частоты
на маршрутах (90 и 40 запросов в минуту с адреса). Недоступность геокодера —
ответ 503 `GEOCODER_UNAVAILABLE` с текстом «поставьте точку на карте
вручную»; форма при этом продолжает работать.

**Публичные серверы OSM — только для разработки.** В production сервер не
стартует, пока `PHOTON_BASE_URL`/`NOMINATIM_BASE_URL` указывают на них
(`config/env.ts`): нужен свой Photon/Nominatim с выгрузкой OSM по Северному
Кавказу или платный поставщик за тем же интерфейсом.

### Карта

Одна карта на всё приложение — Leaflet в WebView (`LeafletMap.tsx`), в
веб-сборке — в iframe (`LeafletMap.web.tsx`). Метку двигают командами без
перезагрузки страницы. Подложка — стандартные тайлы OpenStreetMap (тёмная
тема — CSS-фильтр); страница открывается от имени своего API, чтобы запросы
тайлов шли с Referer, как требуют правила OSM. Для магазинной сборки тайлы
меняются переменной `EXPO_PUBLIC_MAP_TILE_URL` на своего поставщика.
CARTO отклонён: без ключа тайлы приходят с водяным знаком «API KEY REQUIRED».

### Телефон

Контактный телефон объявления — российский мобильный: в поле закреплено
«🇷🇺 +7», вводятся 10 цифр, показ «+7 950 123-45-67». `9501234567`,
`89501234567`, `+79501234567`, вставка с пробелами и скобками — одно и то
же; лишние «+7»/«8» в начале отбрасываются. Неполный номер не сохраняется
ни клиентом, ни сервером (сообщение «Номер неполный: нужно ещё N цифр»).
Хранение: `contact_phone` в E.164 плюс `contact_phone_country_code` и
`contact_phone_national` — чтобы позже добавить другие страны без
миграции данных. Вход по телефону не менялся (там по-прежнему выбор страны).

### Миграции и перенос данных

- `20260930100000_listing_location` — поля, типы, CHECK, заполнение частей
  телефона и места из справочника городов для объявлений без точки;
- `20260930100100_listing_location_search` — город, село и районы в
  полнотекстовом поиске;
- `20260930100200_listing_feed_date_index` — частичный индекс ленты по дате
  для широких кругов.

`npm run db:migrate:listing-locations --workspace @dagestan/api` дозаполняет
адреса у объявлений с точкой через геокодер (медленно, с паузами — правило
Nominatim). Объявлениям без точки координаты не придумываются: они ищутся по
центру своего города, а автор видит в правке просьбу указать место.

## Последствия

- Производительность на 100 тыс. объявлений: лента по дате в широком круге
  — единицы миллисекунд (частичный индекс), счётчик 66–284 мс, «Сначала
  ближе» в плотном круге 25 км — около 0,5 с. Последнее — известное
  ограничение: при росте базы нужен предрасчёт или ограничение глубины.
- Районы городов больше не фильтр поиска: их заменил радиус. Справочник
  районов остаётся для подписи места.
- Поставщиков геокодера и тайлов в production нужно выбрать и оплатить до
  запуска — это отдельное решение, код к нему готов.
