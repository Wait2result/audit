# ADR-0011: Умный поиск (Global Smart Search) на локальной модели

**Статус:** принято, первый слой (2026-10-03)

## Контекст

Человек хочет написать «Toyota Succeed до 1.2 млн, автомат» или «что сегодня
идёт в Каспийске» вместо того, чтобы открывать раздел и выставлять фильтры.
Разделы приложения (объявления, кино, новости, доставка) уже умеют искать —
у каждого свой сервис, свои справочники и свои проверки. Нужен единый вход,
который понимает естественную фразу, но не дублирует эти сервисы и не
доверяет языковой модели данные.

## Решение

### Модель — только переводчик фразы в структуру

Модель не имеет доступа к базе, не выполняет SQL и HTTP-запросы, не выбирает
адреса и не пишет ответ человеку. Она возвращает **намерение** строгой
версионируемой схемы (`smartSearchIntentSchema`, `packages/shared`). Всё
остальное делает сервер:

```
фраза → AiProvider → намерение (JSON) → проверка схемой → раздел (реестр)
      → сверка чисел с фразой → контекст → нормализация по справочникам раздела
      → СУЩЕСТВУЮЩИЙ сервис раздела → ответ из найденных данных
```

Невалидный JSON, чужая версия схемы, неизвестный раздел, неизвестное имя
фильтра — ответ отклоняется **целиком** (`status: error` и `fallback` на
обычный поиск). Неизвестное **значение** (марка, модель, город, вариант
характеристики) не применяется и показывается в `ignored`/`unresolved` или
превращается в уточнение.

### Намерение (версия 1)

`schemaVersion`, `intent` (search / refine / action / unknown), `domain`
(listings / cinema / news / delivery / null), `query`, `filters` (точные
условия), `preferences` (пожелания: «желательно», «по возможности»),
`location` (`city`, `nearMe`, `preferred`), `time` (`date`, `from`, `to`,
`period`), `sort`, `clarification`, `confidence`, `unresolved`, `subqueries`
(до трёх, без вложенности). Значение фильтра — строка, число, логическое,
список или границы `{min, max}`. Имя фильтра — латиница и только из белого
списка раздела.

### Разделы — адаптеры в реестре

| Раздел | Существующий сервис | Что берёт умный поиск |
|---|---|---|
| listings | `ListingsService.list`, `ListingCategoriesService.catalogue()` | категории, поля, справочники марок/моделей (в т.ч. расширенные), написания (`aliases.ts`), классификатор заголовков; итоговый запрос проходит `listingListQuerySchema` |
| cinema | `CinemaService.getSchedule` | расписание города на дату; фильм, жанр, кинотеатр, формат и время отбираются из реального расписания |
| news | `NewsService.getFeed` | лента города/Дагестана/России/мира; день и тема отбираются из свежих страниц ленты |
| delivery | `PlacesService.list`, `CategoriesService.list`, `PlacesService.cuisines` | витрина заведений с доставкой: блюдо/название, кухня из списка города, плитка категории, вид заведения, «открыто сейчас», «за N минут»; запрос проходит `placeListQuerySchema` |

Новый раздел (погода, магазины) — новый класс `DomainAdapter` и значение в
`SMART_SEARCH_DOMAINS`; маршрутизатор, разбор фраз и ответ не меняются.

### Числа не придумываются

Каждое число модели от 100 и выше сверяется с числами, которые человек
написал (`isGroundedNumber`: «1.2 млн», «40 тысяч», «до миллиона», «70к»,
«1 ТБ»). Не нашлось — условие убирается; для цены объявлений сервер
переспрашивает «До какой цены?». «Недорого», «дёшево» ценой не становятся.
Мелкие числа (комнаты из «двушки», минуты) не сверяются.

### Сверка с фразой (по реальной оценке на Qwen3)

Реальный прогон (docs/smart-search-real-evaluation.md) показал, что Qwen3 8B дописывает то,
чего человек не говорил. Поэтому сервер применяет значение модели, только если оно названо:

- сделка и срок аренды — при словах «купить/снять/посуточно/помесячно…»; правило сервера:
  жильё до 200 000 ₽ без таких слов — помесячная аренда;
- день — при «сегодня/завтра/вчера» или дате; час — если он есть во фразе; иначе окно
  времени суток сервера;
- город — если он назван во фразе (с точностью до падежа); город, названный во фразе, но
  пропущенный моделью, берётся из фразы;
- границы «от/до» — при соответствующих словах, иначе значение точное.

Поля, у которых есть своё место (date, time, city, location, period, sort, query), в
filters не роняют ответ, а отбрасываются с пометкой. Поля, которые раздел честно не
умеет (цена в доставке и кино), помечаются «не применено». Неизвестные имена по-прежнему
отклоняют ответ целиком.

Страховка нормализатора объявлений: то, что модель пропустила или разобрала неверно,
ищется во фразе по справочникам — модель по написанию («камри»), значения полей категории
(«автомат», «ИЖС», «SSD»), категория по названию и классификатору объявлений. Только
точные совпадения и только для отсутствующего; ничего не придумывается. Запрос объявлений
без предмета и условий («дёшево», «рядом») — уточнение, а не вся доска.

### Условия и пожелания

`filters` сужают выдачу; `preferences` — нет, они показываются отдельно с
пометкой, учтено ли пожелание. Мягкого ранжирования у разделов нет, поэтому
пожелание по характеристике выдачу не меняет; пожелание по месту в
объявлениях — это поиск по всему Дагестану с сортировкой «сначала ближе».

### «Вечером» — правило сервера

Время суток задают константы `DAY_PERIOD_WINDOWS` (утро 06–12, день 12–17,
вечер 17–24, ночь 22–24), модель возвращает только слово.

### Контекст уточнений

Redis, ключ `smart-search:ctx:{пользователь|anon}:{sessionId}`, срок —
`SMART_SEARCH_CONTEXT_TTL_SECONDS` (20 мин), не больше 4 КБ. Хранится одно
последнее намерение (без текста фраз, координат и персональных данных).
`refine` дополняет его («а автомат?»), смена марки сбрасывает модель, смена
категории — характеристики прежней, другой раздел — новый поиск.

### Модель и её отказы

`AiProvider` — прослойка: `OllamaProvider` (по умолчанию `qwen3:8b`,
`POST /api/chat`, `stream: false`, `think: false`, `temperature: 0`, JSON
Schema в `format`, предел времени и размера ответа) и `DisabledAiProvider`.
Имя модели в логике поиска не используется. Флаги `SMART_SEARCH_ENABLED` и
`AI_ENABLED` по умолчанию выключены; без модели умный поиск отвечает
`status: error` с `fallback: text_search`, разделы работают как раньше.

### Безопасность

Текст человека — недоверенные данные: отдельное сообщение с пометкой,
без разделителей подсказки и управляющих символов, до 300 знаков. Модель не
получает секретов, токенов, координат и идентификаторов пользователя.
Журнал — исход, разделы и время; текст и ответ модели — только при
`AI_DEBUG_LOG` (в production запрещено проверкой конфигурации). Лимит —
30 фраз в минуту с адреса.

## Ограничения первого слоя

- У новостей нет поиска по словам: тема и «за сегодня» отбираются из трёх
  свежих страниц ленты (до 150 новостей), а не из архива.
- У кино нет поиска по названию: отбор идёт по расписанию города на дату.
- Пожелания не ранжируют выдачу (кроме места в объявлениях).
- Города — только из списка приложения; «Владивосток» — уточнение.
- Составной запрос — независимые части без связей между ними.
- Оформление заказа, покупка, оплата, отслеживание курьера — `unsupported`.
- Мобильного экрана ещё нет: контракт (`SmartSearchResponse`) готов в
  `packages/shared`.
