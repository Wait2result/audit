# ADR-0013: Основные типы техники и их направления

**Статус:** принято (2026-10-07)

## Контекст

В разделе «Транспорт» было четырнадцать подкатегорий одним списком:
«Автомобили», «Автозапчасти», «Мотозапчасти», «Запчасти для грузовиков»,
«Шины и диски», «Автоаксессуары»… То же в «Электронике». Детское автокресло,
магнитола, коврики и масло жили в «Автоаксессуарах» или «Автозапчастях»
вперемешку, а у мотоцикла, грузовика и телефона своих направлений
(экипировка, прицепы, чехлы) не было вовсе.

## Решение

### Дерево: раздел → основной тип → направление

```
Транспорт
├── Автомобили          ← основной тип (узел, своих объявлений нет)
│   ├── Автомобили      ← сама техника
│   ├── Запчасти
│   ├── Шины и диски
│   ├── Автоаксессуары  ← направление: тип товара «Коврики» — поле, не категория
│   ├── Детские автокресла
│   └── …
├── Мотоциклы, Грузовики, Спецтехника, Водный транспорт
└── Прочий транспорт    ← обычная подкатегория прямо в разделе
```

- Одиннадцать основных типов (`MAIN_TYPES`, `packages/shared/src/constants/catalog/main-types.ts`):
  автомобили, мотоциклы, грузовики, спецтехника, водный транспорт, телефоны,
  ноутбуки, компьютеры, телевизоры, бытовая техника, климатическая техника.
  Разделы без типов техники (недвижимость, услуги, работа…) остаются
  двухуровневыми.
- Направления — 59 записей реестра `GOODS_DIRECTIONS`
  (`catalog/goods-directions.ts`) плюс сама техника и её запчасти. Каждое
  направление — подкатегория дерева; глубже трёх уровней дерево не идёт.
  Набор направлений у каждого типа свой: у телефона нет «Шин», у автомобиля —
  «Экипировки».
- **Тип товара** («Коврики», «Магнитолы», «Шлемы») — поле объявления
  `goodsType` со справочником направления `goods_type_<ключ>`, а не четвёртый
  уровень. У шин — существующее поле `tireType`, у аксессуаров телефона —
  `accessoryType`.
- Существующие подкатегории сохранили коды (`transport-parts`,
  `transport-tires`, `electronics-accessories`…): узлы основных типов
  добавлены над ними, объявления не переезжали. Дерево собирается функцией
  `withMainTypes` из реестра — новое направление добавляется одной записью.

### Одно объявление — одна классификация

«Коврики Toyota Succeed» — это `transport-accessories` (основной тип —
автомобили, направление — автоаксессуары), тип товара `floor_mats`, а Toyota
Succeed NCP165 — строка «Подходит к» (слой `listing_compatibility`, ADR-0012).
Слой «Подходит к» теперь есть у всех направлений, где он имеет смысл
(`catalogLayer`): у ковриков, магнитол, багажников, тюнинга, шин, чехлов,
пультов; номера детали — только у запчастей. У автохимии, автокресел и
аккумуляторов совместимости нет.

### Переезд того, что стало направлением

Из таксономии запчастей убрано то, что получило своё направление:
аккумуляторы (авто, мото) → «Аккумуляторы», масла и жидкости → «Автохимия»,
навесное грузовиков и спецтехники → «Навесное оборудование», гусеницы целиком →
«Шины и гусеницы», лодочный мотор / винт / навигация → свои направления,
пульты ТВ и кондиционеров → «Пульты» / «Аксессуары», чехлы, стёкла и
зарядки телефона → свои направления. Пункты справочников не удаляются, а
выключаются сидом; объявления переезжают только по явным правилам
`CATEGORY_RELOCATIONS` через `db:migrate:listings-v2` (план, `--dry-run`,
никаких удалений).

### Поиск

- Индекс запчастей (`search/parts.ts`) включает типы товара направлений:
  «коврики на суксид» → `transport-accessories`, `goodsType=floor_mats`,
  «Подходит к» Toyota Succeed. В индекс идут только явные синонимы типов
  («коврики», «магнитола»), не их названия — иначе «куртка» уехала бы в
  мотоэкипировку.
- Названия направлений («автохимия», «кондиционер», «экипировка») — обычные
  слова категорий в словаре; одно такое слово открывает направление.
- Марка и модель техники во фразе у направлений — это «Подходит к», а не
  бренд товара («зимняя резина на суксид»).
- Неоднозначное — вопрос с вариантами, ведущими в то место, где объявление
  живёт: «аккумулятор» → «Аккумуляторы» / Телефон / Ноутбук…

### Тип объявления вместо «Купить / Снять»

«Продать», «Купить», «Сдать», «Снять» — действия, а не категории и не
фильтры. Подача: «Продам / Сдам» (как было). Поиск: фильтр «Тип объявления» —
«Продажа / Аренда» (существительные), без глаголов.

## Ограничения

- «Комплектующие» и «Запчасти» у компьютеров не разделены: таксономия
  комплектующих одна (процессоры, видеокарты…), отдельной для ремонта
  брендовых ПК и моноблоков нет.
- Саундбары остаются в «Аудиотехнике», наушники — там же (не в телефонах):
  иначе одна вещь жила бы в двух местах.
- У водного транспорта и климата моделей в справочнике нет — «Подходит к» с
  моделью текстом.
- Объявления, у которых тип товара при переезде неоднозначен (чехол
  непонятного вида), переезжают без типа — продавец выберет при правке.
