# ADR-0009. Проверка приложения на телефоне через интернет

**Статус:** принято (2026-09-29)

## Контекст

Проверять приложение удобнее всего на настоящем телефоне, и не всегда он в
одной Wi-Fi сети с компьютером. Для этого у Expo есть режим
`expo start --tunnel`, а у нас — `start-dev-tunnel.bat`, который поднимал
три вещи: сервер API, туннель ngrok к нему и Metro со своим туннелем Expo.

Схема ломалась регулярно, и каждый раз по-разному:

- **Туннель Expo не поднимался.** `expo start --tunnel` использует пакет
  `@expo/ngrok` со встроенным ngrok 2.3 — он создаёт туннель через локальный
  API агента, который ngrok убрал в третьей версии. Итог — «ngrok tunnel took
  too long to connect» при исправной сети. Подмена бинарника не помогает:
  несовместим сам способ.
- **Второй туннель ngrok завести нельзя.** Бесплатный тариф ngrok даёт один
  активный туннель на аккаунт (`ERR_NGROK_334`) и запрещает выбирать
  поддомен; бесплатные туннели других сервисов (localtunnel) отваливаются
  через несколько минут.
- **Телефон зависал на «Opening project…».** Expo CLI при выдаче манифеста
  ходит на серверы Expo за подписью; когда этот поход не удаётся, манифест
  отдаётся с ошибкой 500, а на телефоне это выглядит как бесконечная загрузка.
- **Metro не видел новых папок**, появившихся в `packages/shared/dist` пока он
  работал, — «Unable to resolve module».
- **Node не ходил в интернет по HTTPS вообще** (`fetch` к google.com висел до
  таймаута), хотя `curl` отвечал мгновенно: IPv6 на этом компьютере не
  маршрутизируется, а Node пробует IPv6-адрес первым и не переключается.
  Именно так падали походы Expo CLI на свои серверы
  (`UnexpectedServerError`) и не проходила подпись манифеста. Лечится флагами
  `--dns-result-order=ipv4first --no-network-family-autoselection` (одного
  первого недостаточно): файлы запуска ставят их через `NODE_OPTIONS` для
  всех окон, `scripts/start-mobile.js` — для Metro, а
  `scripts/show-mobile-qr.js` ходит по IPv4 явно (`family: 4`).

## Решение

Один туннель на всё. Сервер API в разработке умеет пробрасывать к Metro всё,
что не адресовано ему самому (`/api`, `/docs`, `/health` остаются за сервером,
остальное — GET/HEAD и WebSocket — уходит на Metro). Включается переменной
`MOBILE_TUNNEL_PROXY_PORT=8081` в `.env` и не существует в production
(`apps/api/src/main.ts`).

Metro запускается через `scripts/start-mobile.js --tunnel`, который:

- ставит `EXPO_PACKAGER_PROXY_URL` в адрес туннеля сервера — через него Expo
  строит QR-код и ссылки в манифесте, ничего не зная про свой туннель;
- ставит `EXPO_PUBLIC_API_URL` в тот же адрес плюс `/api/v1`, поэтому в
  `apps/mobile/.env` адрес больше не хранится и режим Wi-Fi не зависит от
  туннеля;
- добавляет `--offline` — манифест подписывается анонимно, без серверов Expo;
- фиксирует порт 8081 и закрывает процесс прошлого запуска, если он его держит.

`start-dev-tunnel.bat` перед стартом закрывает окна прошлого запуска и
лишние ngrok, собирает `packages/shared` (чтобы и сервер, и Metro видели
свежий код) и открывает QR-код только после того, как
`scripts/show-mobile-qr.js` получил через туннель манифест приложения — то
есть ровно то, что запросит Expo Go. Если какое-то звено не готово, скрипт
называет его и что сделать.

### Общий пакет — из исходников (дополнено 2026-09-29)

Ошибка «Unable to resolve module ./constants/…js from packages/shared/dist/
index.js» возвращалась снова и снова: приложение брало `@dagestan/shared`
из собранной папки `dist`, и новый файл shared появлялся там только после
сборки, а уже запущенный Metro туннеля (порт 8081) новый файл в `dist` не
видел. Проверка в браузере шла через другой экземпляр Metro (8082) и
ошибку не показывала.

Теперь:

- `apps/mobile/metro.config.js` отдаёт `@dagestan/shared` из
  `packages/shared/src` (импорты `.js` внутри shared отображаются на
  `.ts`). Сборка shared для приложения не нужна; новый файл виден сразу —
  проверено добавлением файла при запущенном Metro.
- `scripts/start-mobile.js` всегда запускает Metro с `--clear`.
- `npm run check:mobile` запрашивает у Metro на 8081 настоящий бандл iOS и
  Android — ровно то, что скачивает телефон — и падает на любой ошибке
  сборки. Это обязательная проверка после правок приложения или shared;
  проверка в браузере её не заменяет.

Сервер и панель по-прежнему используют собранный `dist` (Node без сборщика
не читает TypeScript).

### Сторож и автозапуск (дополнено 2026-09-30)

Сервер, туннель и Metro жили в трёх отдельных окнах (а при работе с
ассистентом — в его фоновых задачах). Закрылось окно, закончилась сессия,
отвалился туннель — и телефон показывал «не запускается», пока всё не
поднимут руками.

Теперь их держит один процесс — `scripts/dev-supervisor.js`:

- раз в 15 секунд проверяет Docker, базу, сервер (`/health`), туннель
  (локальный API ngrok) и Metro (`/status`) и сам запускает то, что не
  отвечает; работающее не трогает;
- работает без окон, вывод процессов — в `.dev-logs/`;
- запускается при входе в Windows: `scripts/install-autostart.js` кладёт
  файл `Dagestan Dev.vbs` в «Автозагрузку» пользователя (без прав
  администратора);
- перед запуском сервера пересобирает общий пакет, если исходники новее.

Команды: `npm run dev:status` — что работает; `npm run dev:stop` —
остановить; `npm run dev:autostart` — включить автозапуск и запустить;
`npm run dev:autostart -- --remove` — выключить автозапуск.
`start-dev-tunnel.bat` теперь перезапускает всё через сторожа и показывает
QR-код.

Проверено: после принудительного завершения сервера, туннеля и Metro
сторож вернул все три без участия человека (менее трёх минут); холодный
запуск через файл автозагрузки — 42 секунды.

## Последствия

- Файл запуска идемпотентен: если что-то отвалилось, его просто запускают
  ещё раз. Адрес для телефона постоянный —
  `exp://raving-amends-periscope.ngrok-free.dev`.
- Горячая перезагрузка работает и через туннель: WebSocket Metro
  проксируется тем же путём.
- Адрес сервера для приложения задаётся при запуске, а не в файле: одно
  место, где он может разойтись, исчезло.
- Ограничение остаётся: один активный туннель означает, что панель
  управления (`apps/web`) через интернет не открыть — ей это и не нужно.
- Если во время работы Metro в `packages/shared/dist` появляется новая папка,
  Metro нужно перезапустить — запустить `start-dev-tunnel.bat` ещё раз.

### Запуск вне приложения Claude (дополнено 2026-10-01)

Сторож, запущенный из сессии ассистента, всё равно умер вместе с ней: всё,
что запускается из приложения Claude, живёт в его задании Windows (job) и
закрывается при выходе, сколько бы `detached` ни ставить. Поэтому
`install-autostart.js` запускает `Dagestan Dev.vbs` через `explorer.exe` —
процесс становится потомком Проводника, как при входе в Windows.

Вторая ловушка: приложение Claude видит `AppData` через свою «песочницу».
`ngrok.yml` с ключом был создан оттуда, и ngrok, запущенный снаружи, его не
находит (`ERR_NGROK_4018`). Ключ теперь лежит в `.env` (`NGROK_AUTHTOKEN`) и
передаётся ngrok через переменную окружения.

### Шлюз и быстрая загрузка (дополнено 2026-10-05)

Телефон показывал «Could not connect to development server», а приложение
открывалось по минуте. Замеры нашли две причины:

1. **Сжатие в Metro.** Expo Go и ngrok просят сборку сжатой, а Metro сжимает
   9-мегабайтную сборку на лету 41–44 секунды (без сжатия отдаёт её за
   0,8 с). Туннель здесь ни при чём: интернет компьютера отдаёт 1,1 МБ/с.
2. **Metro за сервером API.** Сборка шла через прокси внутри сервера, а сервер
   перезапускается при каждой правке кода (`nest --watch`) — в эти секунды
   приложение не скачивалось вовсе.

Решение — **шлюз** `scripts/dev-gateway.js`: отдельный маленький процесс без
зависимостей на порту `DEV_GATEWAY_PORT` (3080). Туннель ngrok смотрит на
него, а не на сервер:

- `/api`, `/docs`, `/health`, `/l/` → сервер API; пока он перезапускается —
  быстрый ответ `502 API_RESTARTING`, а не обрыв;
- всё остальное (сборка, ресурсы, манифест, WebSocket горячей
  перезагрузки) → Metro. Сборку шлюз берёт у Metro несжатой и сжимает сам
  (brotli 5 или gzip 6): 1,1 с вместо 41 с, 1,5 МБ вместо 9,3 МБ.

Сторож запускает шлюз, проверяет его (`/__gateway`) и перезапускает туннель,
если тот ведёт не на шлюз. Сразу после запуска Metro сторож сам запрашивает
сборки iOS и Android (**прогрев**): первая сборка после перезапуска занимает
1–2 минуты, и теперь её ждёт сторож, а не телефон.

Замеры через настоящий туннель: сборка iOS — 1,9–3,5 с (было 45–50 с),
манифест — 1 с; при убитом сервере API сборка по-прежнему скачивается за
3,8 с. Прокси Metro внутри сервера (`MOBILE_TUNNEL_PROXY_PORT`) оставлен как
запасной путь, туннель им больше не пользуется.
