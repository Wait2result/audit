# Платформа «Дагестан»

Мобильное приложение и серверная часть для жителей и гостей Республики Дагестан:
погода, кино, новости, рестораны с доставкой, магазины, попутчики, недвижимость.

Города первого этапа: **Махачкала, Каспийск, Дербент**.

> Полное техническое задание и архитектурный план — в `docs/`.

## Первый запуск

**1. Установить зависимости** (нужно один раз, займёт пару минут)

```bash
npm install
```

**2. Создать файл настроек**

Скопируйте `.env.example` в `.env` и заполните. В Windows PowerShell:

```bash
Copy-Item .env.example .env
```

Затем сгенерируйте секретные ключи и подставьте их в `.env` вместо строк `CHANGE_ME`:

```bash
node -e "const c=require('crypto');console.log('JWT_ACCESS_SECRET='+c.randomBytes(48).toString('base64url'));console.log('JWT_REFRESH_SECRET='+c.randomBytes(48).toString('base64url'));console.log('ENCRYPTION_KEY='+c.randomBytes(32).toString('base64'))"
```

> ⚠️ Файл `.env` содержит настоящие пароли и ключи. Он никогда не попадает в git
> и не пересылается в мессенджерах. При потере `ENCRYPTION_KEY` зашифрованные
> данные восстановить невозможно.

**3. Поднять базу данных и Redis**

```bash
npm run infra:up
```

**4. Создать таблицы и заполнить справочники**

```bash
npm run db:migrate
```

```bash
npm run db:seed
```

Скрипт заполнения выведет в консоль **логин и пароль владельца системы**.
Сохраните их в менеджер паролей — второй раз пароль не показывается.

**5. Запустить сервер**

```bash
npm run dev:api
```

Открыть в браузере: **http://localhost:3000/docs** — интерактивная документация API,
где каждый метод можно вызвать прямо со страницы.

**6. Запустить панель управления** (в отдельном окне терминала, сервер должен работать)

```bash
npm run dev:web
```

Открыть в браузере: **http://localhost:3001** — вход по телефону и паролю владельца
системы, которые показал скрипт заполнения справочников.

> Панель — это тот самый «сайт», куда вы заходите как владелец. Сам сервер (порт 3000)
> страниц для человека не имеет: он только отдаёт данные приложению и панели.

## Автоматическая проверка сценариев

Когда сервер запущен, одна команда прогоняет всю цепочку: регистрация, вход,
обновление сессии, права доступа — и, главное, проверяет, что **срабатывает
защита**: пауза между SMS, отклонение неверного кода, обнаружение кражи токена,
отказ в доступе к админскому разделу.

```bash
npm run test:e2e
```

Чтобы проверка захватила и вход владельца системы, укажите его пароль:

```bash
ADMIN_PASSWORD=ваш_пароль npm run test:e2e
```

## Как проверить, что регистрация работает

SMS в режиме разработки **не отправляются** — код печатается в консоль сервера
и возвращается в ответе в поле `devCode`. Это позволяет тестировать регистрацию,
не подключая платного SMS-провайдера.

1. Откройте http://localhost:3000/docs
2. `POST /api/v1/auth/otp/request` → тело: `{"phone": "89280000000", "purpose": "registration"}`
   Ответ содержит `devCode` — это и есть код из «SMS».
3. `POST /api/v1/auth/otp/verify` → тот же телефон, `code` из предыдущего шага,
   `purpose: registration`. В ответе — `verificationToken`.
4. `POST /api/v1/auth/register` → `verificationToken`, `password`, `firstName`,
   `acceptedTerms: true`. В ответе — данные пользователя и токены доступа.
5. `POST /api/v1/auth/login` → телефон и пароль. Должны прийти те же токены.

Проверьте заодно защиту: повторите шаг 2 сразу же — сервер откажет с сообщением
о паузе между отправками. Так и должно быть.

## Важные правила работы с проектом

1. **Секреты не попадают в код.** Все ключи — только в `.env` или в защищённом
   хранилище секретов на сервере.
2. **Приложение не ходит в базу напрямую.** Только через API.
3. **Новый город — это строка в таблице `cities`**, а не изменение кода.
4. **Каждое административное действие пишется в журнал аудита.**
5. **По умолчанию эндпоинт закрыт.** Открытость указывается явно декоратором
   `@Public()` — так забытая проверка ошибается в безопасную сторону.

## Мобильное приложение

Два готовых файла запуска в корне проекта — двойной щелчок, и всё поднимается
само (Docker, база, сервер, приложение):

| Файл                   | Когда                                                  |
| ---------------------- | ------------------------------------------------------ |
| `start-dev.bat`        | телефон и компьютер в одной Wi-Fi сети                 |
| `start-dev-tunnel.bat` | телефон где угодно, нужен только интернет (через ngrok) |
| `stop-dev.bat`         | остановить всё                                         |

В конце открывается картинка с QR-кодом — отсканируйте её приложением
**Expo Go** (App Store или RuStore). Для режима через интернет адрес
постоянный: `exp://raving-amends-periscope.ngrok-free.dev`, и файл сначала
проверяет всю цепочку — если что-то не готово, он скажет, какое окно
посмотреть. **Если что-то отвалилось — просто запустите файл ещё раз**, он
закроет всё старое и поднимет заново. Как это устроено и почему не
`expo start --tunnel` — `docs/ADR/0009-туннель-разработки.md`.

Вручную из консоли:

```bash
npm run dev:mobile           # Wi-Fi
npm run dev:mobile:tunnel    # через интернет (сервер и ngrok должны быть запущены)
```

Откроется меню Expo: клавиша **w** — открыть в браузере, **a** / **i** —
эмуляторы. Адрес сервера приложение определяет само: в браузере это
localhost, на телефоне в Wi-Fi — адрес вашего компьютера в сети, через
интернет — адрес туннеля.

> SMS в режиме разработки не отправляются. Код подтверждения показывается
> прямо на экране ввода — можно пройти регистрацию целиком, ничего не подключая.
